UncertaintyLab

A local browser app that samples uncertain inputs, evaluates a bounded mathematical expression, and shows the output distribution with summary statistics.

Source snapshot: 9b0fe6e

One run, from click to chart

The Python server returns static files from public/ on 127.0.0.1. Calculation and rendering stay in the browser; there is no API, database, or browser storage.

A three-stop reference route

  1. Start at the user action. In public/index.html, find #run-button and the preloaded form. In public/app.mjs, search for readRows() and handleRun(); the handler coordinates validation, computation, and result visibility.
  2. Follow the safe expression path. In public/expression.mjs, inspect parseExpression() and evaluateExpression(). They accept a bounded math grammar and explicit function allowlist instead of evaluating arbitrary source code.
  3. Follow samples to pixels. In public/simulation.mjs, search runSimulation() and createHistogram(); then open public/histogram.mjs at renderHistogram(). app.mjs writes the numeric summary while the renderer draws the SVG bars and nominal/mean markers.

Default values and visible wording

public/index.html contains the initial rows and labels; public/app.mjs contains DEFAULT_EXPRESSION and the built-in mass/unit match.

Expression grammar

Update the tokenizer/parser and allowlisted functions in public/expression.mjs, then extend tests/expression.test.mjs for accepted and rejected syntax.

Sampling and fixed run settings

public/simulation.mjs defines SAMPLE_COUNT, RANDOM_SEED, normal sampling, summary statistics, and histogram bins.

Chart layout and style

Change SVG coordinates in public/histogram.mjs and colors/spacing in public/styles.css; check both narrow and wide viewports.

A practice to reuse

Turn an important numerical expectation into an observable check. The scope fixes the rectangle's nominal mass at 390 g; tests/simulation.test.mjs checks that value separately from the random sample mean, and another test checks that seed 42 reproduces a run. On another project, state the invariant first, then test it independently from noisy or probabilistic output.

The final browser review also exercised a changed input and an invalid expression; the learner confirmed that edits recalculate and invalid input leaves no stale result. The narrow-chart check compared the measured container width with the SVG viewBox rather than relying on source inspection alone.

Optional transfer reflection: In a future scientific project, what numerical expectation could you define as an invariant and test separately from probabilistic output?

Run it again

From the repository root, run:

python3 -m http.server 8000 --bind 127.0.0.1 --directory public

Open http://127.0.0.1:8000/. Optional calculation tests: node --test tests/*.test.mjs.
